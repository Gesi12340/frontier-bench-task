# Debugging a Silent Data Loss Bug in a Multi-Service Payment System

You're given a containerized payment processing system with three microservices: an API gateway, a transaction processor, and a persistent ledger. The system processes payment requests asynchronously. A customer reports that deposits they initiated are confirmed in the UI but never appear in their account ledger — the money vanishes silently.

Your job is to **identify the root cause of the data loss, provide a fix, and verify it works**.

## What you have

- A running multi-container system (`docker-compose.yaml`) with all three services
- Access to application logs from each service
- The ability to execute new transactions against the live system
- Source code for all services (Python with Flask/asyncio)
- A test harness to simulate deposits and verify end-to-end correctness

## What the bug looks like

- Transactions show as "confirmed" in the gateway
- The transaction processor logs indicate processing began
- But the ledger never records the transaction
- No error messages; the system is silent about the failure
- The bug is probabilistic — it happens under load or after certain timing patterns, not every time

## The challenge

This is not a simple logic error. The root cause involves one of these issues:
1. A race condition between asynchronous commit and rollback operations
2. A silent exception in a background worker that nobody logs
3. A transaction isolation level mismatch between two services
4. An off-by-one bug in a state machine that causes valid transactions to be dropped

You must:
1. Reproduce the bug reliably (write a script that triggers it consistently)
2. Instrument the system to surface the hidden failure
3. Identify which issue is the actual root cause
4. Fix the bug in the source code
5. Verify the fix works under load

## Expected output

Create a file `/app/fix_report.json` with this exact structure:

```json
{
  "root_cause": "<one of: race_condition, silent_exception, isolation_level, state_machine_bug>",
  "explanation": "<2-3 sentences explaining what the bug was and why it happened>",
  "fixed_file": "<relative path to the file you modified>",
  "fix_type": "<one of: code_change, config_change, both>",
  "verification_passed": true
}
```

## Hints

- The bug manifests only when transactions arrive within 50ms of each other
- Check the ledger service's exception handling carefully
- Transaction IDs are generated by the gateway; trace one end-to-end
- The processor sometimes writes to the ledger but the write doesn't persist — why?

You have 900 seconds to complete this task. Do not cheat by using online solutions or hints specific to this task.
